# Short Reflection Report

The main challenge in this benchmark was making the workload comparable across four frameworks that use different rendering and reactivity models. A naïve implementation could easily favor one framework by using unstable list identifiers, direct DOM manipulation, or development builds. I therefore used the same task structure and operations in every application, stable task IDs, production-oriented project setups, and a common measurement method based on `performance.now()` plus a browser-paint wait.

Each framework approaches DOM updates differently. React expresses UI as component output derived from state and relies on reconciliation with keyed list elements. Vue uses a reactive data model and `v-for`, while keyed rendering helps preserve item identity. Angular uses signals with the modern `@for` block and explicit `track task.id`, which allows Angular to associate data with DOM nodes efficiently. Svelte moves more work to compilation and uses keyed `{#each}` blocks to update the affected DOM.

The exercise also showed why a single benchmark number is not enough. Initial rendering, partial updates, and deletions stress different parts of each runtime. Performance can also change with browser versions, production versus development mode, keying strategy, and machine conditions. For that reason, I designed the repository to export reproducible JSON measurements rather than hard-code a universal winner. The most useful conclusion is workload-specific: the best framework is the one that meets the application's performance requirements while also satisfying maintainability, ecosystem, developer productivity, and architectural needs.
