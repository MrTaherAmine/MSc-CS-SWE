# Phase 7 Deployment Guide

## Selected production architecture

| Layer | Provider | Purpose |
| --- | --- | --- |
| Web service | Render | Runs Express and serves the compiled React application |
| Database | MongoDB Atlas | Persists users, books, recommendations, ratings, likes, comments, and follows |
| Source and CI | GitHub | Public submission repository and automated verification |
| External catalog | Open Library | Book search, metadata, and cover images |

The frontend and API use the same public origin. This avoids cross-site cookie
complexity and keeps the production deployment to one web service.

## Before deployment

### 1. Push the repository

The final code must be available on the public repository's `main` branch:

```text
https://github.com/MrTaherAmine/booksphere
```

GitHub Actions runs server tests, builds the React client, and validates the
deployment configuration. Render is configured to deploy only after these checks pass.

### 2. Prepare MongoDB Atlas

1. Create or select an Atlas project and cluster.
2. Create a dedicated database user for BookSphere.
3. Add the required network access rule for the Render service.
4. Select **Connect → Drivers → Node.js**.
5. Copy the `mongodb+srv://` connection string, insert the database user's encoded
   password, and use `booksphere` as the database name.

Do not paste this connection string into source code, GitHub, screenshots, or the
GOMYCODE report.

## Deploy using the Blueprint

1. Open:
   `https://render.com/deploy?repo=https://github.com/MrTaherAmine/booksphere`
2. Sign in to Render and authorize access to the repository.
3. Confirm the `booksphere` web service defined by `render.yaml`.
4. Enter `MONGODB_URI` when prompted.
5. Create the Blueprint and wait for the service to become **Live**.

The Blueprint automatically applies:

| Setting | Value |
| --- | --- |
| Runtime | Node.js |
| Region | Frankfurt |
| Plan | Free |
| Build | Install server/client dependencies and compile React |
| Start | `npm start` |
| Health check | `/api/health` |
| Auto deploy | Only after GitHub checks pass |
| `NODE_ENV` | `production` |
| `JWT_SECRET` | Securely generated by Render |

## Expected deployment evidence

Open `https://<service-name>.onrender.com/api/health`. A ready deployment returns:

```json
{
  "success": true,
  "service": "BookSphere API",
  "status": "ready",
  "database": "connected",
  "environment": "production"
}
```

The response also contains a current timestamp.

## Production smoke test

Complete these tasks using the assigned Render URL:

1. Load `/` and confirm the discovery page appears over HTTPS.
2. Open `/search`, search by title, author, and genre, and open a book result.
3. Register a new test reader and verify the session remains active after refresh.
4. Rate a book and confirm the average/count update.
5. Add a recommendation and confirm it appears in the relevant community views.
6. Open **For You** and verify the personalized reason is displayed.
7. Like, comment on, and share a recommendation.
8. Open another reader's profile and test follow/unfollow.
9. Open a React route directly (for example `/search`) and refresh it.
10. Confirm `/api/health` returns HTTP 200 with `database: connected`.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Health check returns 503 | Verify `MONGODB_URI`, database credentials, and Atlas network access |
| Build fails | Review Render build logs and GitHub Actions; run `npm run verify:deployment` locally |
| Login does not persist | Confirm the application is opened over HTTPS and `NODE_ENV=production` |
| Direct React route returns 404 | Confirm the deployed commit contains the production SPA fallback in `server/src/app.js` |
| Book covers are blocked | Confirm the response contains the Phase 7 Content Security Policy allowing Open Library covers |
| First request is slow | Render free web services can sleep after inactivity and need time to wake |

## Rollback

If a new deployment fails, Render keeps the last successful version live. From
the Render service dashboard, open **Events**, select a previously successful
deploy, and redeploy that commit.
