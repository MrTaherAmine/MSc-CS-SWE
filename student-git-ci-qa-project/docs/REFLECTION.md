# Short Reflection Report

Working with Git, continuous integration, and quality assurance showed me that reliable software development depends on disciplined processes, not only on writing code. The main challenge with Git was understanding how local changes, branches, commits, and remote repositories relate to one another. Branching is simple in principle, but merge conflicts can become confusing when two contributors modify the same lines. Resolving a conflict carefully taught me to inspect both versions instead of automatically choosing one.

The CI pipeline made the development process more efficient because every push and pull request could be checked automatically. Instead of relying on a developer to remember to run every command, GitHub Actions installs the dependencies, runs ESLint, executes the unit tests, and verifies that the project builds. A failing pipeline provides immediate feedback and prevents defective code from being merged into the main branch.

Version control also improved collaboration because every change had a visible history and could be developed independently on a feature branch. Pull requests created a clear place for discussion and review before merging. Quality assurance practices improved confidence in the application because the grade-calculation functions were covered by automated tests, while the linter detected style problems and common coding mistakes. Together, Git, CI, testing, linting, and peer review created a workflow in which changes were easier to understand, safer to integrate, and simpler to maintain. The exercise demonstrated that software quality is a continuous team responsibility rather than a final step performed after development.
